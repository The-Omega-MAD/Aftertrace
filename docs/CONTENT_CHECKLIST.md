# Official submission checklist

## Product requirements
- [x] Business workflow rather than student-centric utility.
- [x] Hindsight is central to the value proposition.
- [x] One focused persona and workflow.
- [x] Before/after memory demonstration is designed.
- [x] Synthetic realistic data.
- [x] Visible learning loop and human review.
- [ ] Configure Hindsight credentials and run the full demo.
- [ ] Download and use Band AI desktop as required by the problem statement.
- [ ] Record and test the live project demo.

## Team deliverables
- [ ] Each member publishes an 800–1,500 word public article.
- [ ] Each member publishes a LinkedIn post under 800 characters.
- [ ] One public YouTube team video, 2–5 minutes, 1080p minimum.
- [ ] Each member submits their own article and social post.
- [ ] Share the article as a Reddit Link post in one permitted subreddit.
- [ ] Submit the public GitHub repository.
- [ ] Submit the live demo and explain exactly how Hindsight is used.

## Article checklist
- [ ] Title is about the idea/result and mentions Hindsight.
- [ ] Do not mention the event in the title or article.
- [ ] Concrete opening, problem, Hindsight integration, real code snippets.
- [ ] Before/after example and honest limitation.
- [ ] Screenshots and architecture diagram.
- [ ] Public, linkable article URL.

## LinkedIn checklist
- [ ] Do not mention the event.
- [ ] First two lines: no links or hashtags.
- [ ] 3–7 concrete takeaways and a before/after behavior change.
- [ ] Mention Hindsight positively.
- [ ] Under 800 characters.
- [ ] Include the project GitHub link in the main post.
- [ ] First comment: article URL.
- [ ] Another comment: Hindsight GitHub URL.

## Video checklist
- [ ] 2–5 minutes, preferably about 3 minutes.
- [ ] Screen recording with voiceover, 1080p minimum.
- [ ] Show no-memory / memory behavior, retain and recall live.
- [ ] Upload publicly to YouTube; do not submit a Drive-only link.
